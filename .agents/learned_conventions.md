# Project Learned Conventions & Architectural Invariants

- **[MAP-001] (2026-10-27)**: The app embeds `assets/generated/marinduque-map.html` (build output — never edit). Sources live in `assets/map/` (index.html + css/ + js/); always rebuild with `npm run build:map`. `location.hash` selects the mode: `#embed` = compact card (TerminalDetailsScreen), `#full` = fullscreen Map tab. Scope embedded-only layout changes behind `body.embedded` selectors and `EMBEDDED` JS branches so fullscreen chrome stays untouched.

- **[DATA-001] (2026-10-27)**: Roles are database-defined and group-scoped: the super admin assigns one approved chairperson to a jeepney or TODA/tricycle group; that chairperson manages only the assigned group’s terminals, drivers, vehicles, and schedules. Seeded transport records must remain explicitly is_sample=true until locally verified; never invent auth users, driver identities, plates, or live GPS positions. Terminal hours are one validated weekly row per day (PostgreSQL day 0 = Sunday), edited through save_terminal_schedule.
- **[UI-001] (2026-10-27)**: Keep commuter trip planning on the Map tab, and use icon-only location and map controls with descriptive accessibility labels.
- **[UI-002] (2026-10-27)**: Commuter trip planning is available on both Home and Map; retain icon-only location and map controls with descriptive accessibility labels.
- **[UI-003] (2026-10-27)**: Home shows only a destination field with map-pick and submit controls; submit opens Map to calculate and show the route, where the full origin and directions planner remains available.
- **[UI-004] (2026-10-27)**: Keep destination search and full trip planning on the Map tab; do not show destination search on Home. Do not display the 'GPS Map' label.
- **[DATA-002] (2026-10-27)**: Transit routing must permit jeepneys only between different Marinduque municipalities in both directions; tricycle/TODA routes must remain within one municipality and serve no more than five consecutive route-stop intervals.
- **[UI-005] (2026-10-27)**: Trip details must use a road-following map route with street names, turn instructions, distance, and a clearly labelled driving-time estimate. The app details and embedded map share one OSRM road result; never present direct stop-to-stop lines as a road route when routing fails.
- **[UI-006] (2026-10-27)**: Map location picking keeps its prompt at the bottom of the map with no top OK button; tapping the map places a draggable preview pin, and tapping that pin confirms the starting point or destination.
- **[QA-001] (2026-10-27)**: MapLibre location markers must receive setLngLat before addTo; mounting an unpositioned marker caused the stray blue dot and an undefined-lng error. Planned road overlays should render details immediately and schedule geometry drawing for map idle when styles/sources are not ready; returning to Map must refit the road overview.
- **[DATA-003] (2026-10-27)**: Sample transit coverage = one jeepney terminal + one TODA hub per municipality, plus two TODA terminals (service point `egabay-sample-terminal:toda:` and pickup point `...:toda-alt:`; deterministic md5-derived UUIDs) per official PSGC barangay — 218 barangays total (Boac 61, Buenavista 15, Gasan 25, Mogpog 37, Santa Cruz 55, Torrijos 25). Barangay↔barangay tricycle links are `SAMPLE-TRI-LNK-<MUNI>-<NN>` two-stop routes between consecutive PSGC-listed barangays; ordering is list order, not surveyed adjacency. Apply pending local migrations to the hosted project via `npx supabase db push` (project linked); `npm run test:database` (PGlite) is the verification gate and its sample-data counts must be kept in sync when seed coverage changes.
